# practise_platform_channel_flutter

![CI](https://github.com/Bornmajor/practise_platform_channel_flutter/actions/workflows/ci.yml/badge.svg)

A practice project for learning how Flutter talks to **native platform code** (Kotlin on Android): first with hand-written **platform channels**, then with type-safe code generated by **[Pigeon](https://pub.dev/packages/pigeon)**.

## Why platform channels?

Flutter code runs in the **Dart runtime** (inside the Flutter engine), while Android code runs in **ART** (Android Runtime). The two runtimes have separate memory and type systems, so Dart cannot call Kotlin functions directly. Instead, they exchange simple messages (`int`, `String`, `bool`, `List`, `Map`, ...) through a **platform channel**.

## What the app does

A **Device Status** screen that shows the battery level and charging state:

- **Live updates** – the screen updates by itself when the level changes or a charger is plugged in or unplugged (native → Dart stream).
- **Refresh once (HostApi)** – a one-time read of the level (Dart asks → native answers once). It only returns the level, so the charging state shows as *unknown* until the next live update.

## How it works: Pigeon

The API is described **once** in a Dart contract. Pigeon generates the channel code for both sides, so channel names, method names and data classes always match.

```
pigeons/battery_api.dart  (contract)
          │  dart run pigeon --input pigeons/battery_api.dart
   ┌──────┴───────────────────────────┐
   ▼                                  ▼
lib/pigeon/battery_api.g.dart    android/.../BatteryApi.g.kt
(generated Dart)                 (generated Kotlin)
   │                                  │
battery_screen.dart              BatteryHostApiImpl.kt, BatteryStreamHandler.kt
(calls the API)                  (implements the API)
```

### The contract – `pigeons/battery_api.dart`

```dart
class BatteryInfo {
  int level;
  bool? isCharging; // null = unknown (one-time read)
}

@HostApi()
abstract class BatteryHostApi {
  int getBatteryLevel(); // Dart asks, Kotlin answers once
}

@EventChannelApi()
abstract class BatteryEventApi {
  BatteryInfo batteryUpdates(); // Kotlin pushes many values
}
```

The contract is not part of the app; it is only input for the generator.

### Android – `android/app/src/main/kotlin/com/example/practise_platform_channel_flutter/`

| File | Role |
|---|---|
| `BatteryApi.g.kt` | **Generated.** Kotlin `BatteryInfo`, `BatteryHostApi` interface, `BatteryUpdatesStreamHandler`, codec. |
| `BatteryHostApiImpl.kt` | Implements `getBatteryLevel(): Long` with `BatteryManager`. Throws `FlutterError` on failure. |
| `BatteryStreamHandler.kt` | Extends `BatteryUpdatesStreamHandler`. A `BroadcastReceiver` for `ACTION_BATTERY_CHANGED` (sticky, so the current value arrives immediately) sends `BatteryInfo` through a typed `PigeonEventSink`. Registers in `onListen`, unregisters in `onCancel`. |
| `MainActivity.kt` | Wiring only: `BatteryHostApi.setUp(...)` and `BatteryUpdatesStreamHandler.register(...)`, both with `applicationContext`. |

### Flutter – `lib/`

| File | Role |
|---|---|
| `pigeon/battery_api.g.dart` | **Generated.** Dart `BatteryInfo`, `BatteryHostApi` client, `batteryUpdates()` stream, codec. |
| `battery_screen.dart` | Listens to `batteryUpdates()` in `initState`, cancels in `dispose`. Calls `BatteryHostApi().getBatteryLevel()` on button press. |
| `battery_state.dart` | Sealed class (`BatteryLoading`, `BatterySuccess`, `BatteryError`) rendered with an exhaustive `switch`. |

### Data flow

```
Dart                                              Kotlin (ART)
batteryUpdates().listen()  ─────────────────────►  onListen() → registerReceiver(...)
BatterySuccess(BatteryInfo) ◄── codec (tag 129) ─  sink.success(BatteryInfo(level, isCharging))
          ... battery changes ...
cancel() in dispose  ───────────────────────────►  onCancel() → unregisterReceiver(...)

BatteryHostApi().getBatteryLevel() ─────────────►  BatteryHostApiImpl.getBatteryLevel()
Future<int> / PlatformException  ◄── [value] or ─  return level / throw FlutterError(...)
                                     [code, message, details]
```

### Regenerating after changing the contract

```bash
dart run pigeon --input pigeons/battery_api.dart
dart format lib/pigeon
```

Never edit `*.g.dart` / `*.g.kt` by hand. The generated Dart code is not formatted, and CI checks formatting, so always run `dart format` afterwards. Generated files are committed so CI and other machines can build without running Pigeon.

## Hand-written channels vs Pigeon

This project first used hand-written channels (see the git history and the `feature/battery-method-channel` branch), then switched to Pigeon with the same behavior.

| | Hand-written | Pigeon |
|---|---|---|
| Contract | Unwritten: channel strings + Map keys | One Dart file |
| Dart call | `MethodChannel('.../battery').invokeMethod('getBatteryLevel')` | `BatteryHostApi().getBatteryLevel()` |
| Dart stream | `EventChannel(...).receiveBroadcastStream().map(BatteryInfo.fromMap)` | `batteryUpdates()` → `Stream<BatteryInfo>` |
| Kotlin call | `setMethodCallHandler { if (call.method == ...) }` | `override fun getBatteryLevel(): Long` |
| Kotlin stream | `events.success(mapOf("level" to ..., ...))` | `sink.success(BatteryInfo(...))` |
| Errors | `result.error(...)` / `events.error(...)` | `throw FlutterError(...)` / `sink.error(...)` |
| Channel names | Typed by hand on both sides | Generated: `dev.flutter.pigeon.<package>.<Api>.<method>` |
| Mistakes found | At runtime | At compile time |

Under the hood Pigeon still uses platform channels: a `BasicMessageChannel` per `@HostApi` method and an `EventChannel` per `@EventChannelApi` method.

## Key takeaways

- Objects never cross the channel: each side has its own class, and a codec converts to simple values and back. Pigeon generates both classes and the codec from one definition.
- Dart `int` is 64-bit, so it maps to Kotlin `Long`.
- Channel calls are always **asynchronous**.
- Native errors reach Dart as `PlatformException`.
- Pigeon handles the plumbing; native logic, lifecycle (`onListen` / `onCancel`) and threading are still yours.
- Pair `listen()` in `initState` with `cancel()` in `dispose()` to avoid leaks.
- Pass `applicationContext` (not the Activity) to long-lived native objects.
- After an `await`, check `mounted` before calling `setState`.

## Tests

Widget tests run without Android by **mocking the native side** of the Pigeon channels:

- `test/battery_screen_test.dart` – mocks the generated channel names with Pigeon's codecs. The fake stream sends typed `BatteryInfo` objects, and the fake HostApi uses Pigeon's reply format (`[value]` on success, `[code, message, details]` for errors). Covers loading, charging / not charging, native errors, the one-time read, and `onCancel` on dispose.

```bash
flutter test
```

**CI** (`.github/workflows/ci.yml`) runs on every pull request to `main` and on pushes to `main`: format check, `flutter analyze`, and `flutter test`.

## Running

Android only for now (iOS needs a Mac).

```bash
flutter pub get
flutter run
```

Simulate battery changes on an emulator while the app runs:

```bash
adb shell dumpsys battery set level 42
adb shell dumpsys battery unplug
adb shell dumpsys battery reset
```
